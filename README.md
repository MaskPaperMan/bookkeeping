# 客户往来记账

一个单人、离线、人民币客户收款账本。只记录客户向我支付资金，使用 Python、Tkinter/ttk 和 SQLite。

## 使用 EXE

1. 将 `CustomerLedger-win7-x86.zip` 解压到本地文件夹。
2. 打开文件夹里的 `CustomerLedger.exe`。请保留同目录全部文件，不能单独复制 EXE。
3. 点击“新增客户”，填写客户名称，电话、备注选填。
4. 选择客户，点击“收款”“预付充值”或“还款”，填写金额、日期和备注后保存。

目标系统为 Windows 7 SP1 的 32 位、64 位及较新 Windows。程序包包含 Python 运行环境，用户不需要安装 Python 或 .NET。

**Windows 构建通过 GitHub Actions 生成；成功后可下载 EXE ZIP。Windows 7 仍须完成 `WINDOWS-VALIDATION.md` 的实际兼容验收。源码 ZIP 不是可运行的 Windows 程序包。**

## 三个日常入口

| 按钮 / 选项 | 使用情景 | 余额变化 |
| --- | --- | --- |
| 收款，不勾选其他选项 | 客户直接支付本次金额 | 保存现金收款流水，欠款和预付金不变 |
| 收款，勾选“赊账” | 本次先记账，客户之后再付款 | 增加客户欠款 |
| 收款，勾选“预付金抵扣” | 从客户预付金扣除本次金额 | 优先减少预付金；不足部分另选处理方式 |
| 预付充值 | 客户提前存钱 | 增加预付金，不自动偿还旧欠款 |
| 还款 | 客户偿还旧欠款 | 减少客户欠款，不改变预付金 |

界面只显示“客户欠款”和“预付金余额”。没有向客户付款、应付或我的预付款录入选项。现金收款仅指本次直接收取的金额，也可用于记录转账等收款方式，在备注中说明即可。

### 预付金不足时

例如本次收款 150 元，预付金只有 100 元。勾选“预付金抵扣”后，显示预付抵扣 100 元、剩余 50 元；必须选择：

- **现金收款**：扣除预付金 100 元，另外收取 50 元，客户欠款不变。
- **记为欠款**：扣除预付金 100 元，新增欠款 50 元。

预付金足够时全额抵扣，不新增欠款，也不再次记录现金收入。预付金为零时，整笔金额按所选差额方式处理。收款保存为一条流水，列表“结算明细”显示预付、现金和欠款的拆分。作废该条流水会一起撤销抵扣及新增欠款。

“还款”不能超过客户当前欠款。若客户多付，先按欠款金额记还款，超出部分另记“预付充值”。

金额必须大于零，精确到分。日期使用 `YYYY-MM-DD`，默认为当天。同一天按录入顺序计算；补录旧日期会按该日的可用预付金预览抵扣，并校验后续流水，任何时点不得透支。开始使用前已有欠款可用“收款 → 赊账”补录，并注明“期初欠款”；原有预付金用“预付充值”补录并注明。

## 查看、纠错与导出

- 上半区按名称、电话、备注搜索客户，可筛选有欠款客户、是否包含停用客户。顶部合计始终包含整个账本和停用客户，不随筛选变化。
- 下半区显示所选客户的全部余额；日期和类型筛选仅影响流水列表，不改变余额。清空日期表示不限范围。
- 流水编号按每个客户的录入顺序独立从 1 开始，其他客户记账不会占号。作废记录保留编号，补录旧日期不改变已有编号；筛选后的列表和 CSV 保留原编号，不重新编号。
- 已保存的流水不能直接改写或删除。选中流水，点击“作废选中流水”并填写原因，然后重新录入正确记录。作废记录保留在列表和导出文件中。
- 如果作废早期赊账或充值会导致后面的还款、预付抵扣透支，程序会拒绝。先从后往前作废依赖记录，再重新录入。
- 停用客户仍参与合计，可查看、导出、作废流水，重新启用后可新增往来。只有从未产生流水的客户才可删除。
- “导出客户汇总”导出当前筛选客户的欠款及预付金；“导出当前流水”导出所选客户当前筛选的流水，包含预付抵扣、现金收款、新增欠款明细，以及作废状态、原因和录入时间。
- CSV 使用 UTF-8 BOM，便于 Excel 显示中文。名称、电话和备注以公式符号开头时，会加文本前缀，避免被作为公式执行。

## 数据、备份和升级

Windows 数据目录：`%LOCALAPPDATA%\客户往来记账`，可在资源管理器地址栏粘贴打开。程序底部也显示实际账本路径。

- `ledger.sqlite3`：完整账本。
- `backups`：每天首次启动的自动备份，最多保留最近 30 份 `auto-日期.sqlite3`；以及恢复前的 `before-restore-时间.sqlite3` 备份。恢复前备份不会自动清理。
- 旧账本首次升级前另存 `before-upgrade-时间.sqlite3`，保留全部原始客户、流水、作废信息，增加收款抵扣拆分字段。也支持直接恢复旧版备份，恢复时会升级备份副本，原备份不改动。旧版特殊流水可在“历史记录”筛选中查看，旧付款方向只保留历史记录，不并入客户欠款或预付金。

升级后账本使用数据库版本 2。若回退到旧程序，需使用升级前的备份；旧程序无法读取新版拆分收款记录。
- `ledger.lock`：单实例锁文件，退出或进程结束后系统自动释放，无须删除文件。
- `errors.log`：错误日志，自动轮换保留最近三份，每份最多约 1 MB。

“备份账本”可将当前账本保存到其他目录或 U 盘。“恢复账本”会替换整个账本，而非合并；恢复前先校验备份结构及余额，并自动保存当前账本。备份无效或恢复前备份失败时，不替换当前数据。

自动备份与账本在同一台电脑，建议定期手动备份到外部设备。恢复前备份可以通过“恢复账本”再次选取，用于回退。

更新程序：先备份、关闭程序，再解压新版到新文件夹并运行。数据目录不变，不要删除用户数据目录。首次启动的当日备份发生在记账前；需要保存最新记录时请手动备份。不同 Windows 用户拥有各自独立账本，迁移电脑需备份后恢复。

首版不提供密码、加密、云同步、多账本、订单核销、库存或发票功能。

## 从源码运行和测试

使用 uv 管理项目和虚拟环境；运行不依赖第三方 Python 包，Python 安装需包含 Tkinter。在项目根目录执行：

```console
uv venv --python 3.12 .venv
uv sync --locked
uv run --locked main.py
uv run --locked python -m unittest discover -v
```

`.python-version` 将日常开发固定为 Python 3.12。`pyproject.toml` 和 `uv.lock` 管理运行项目；运行依赖为空，Windows 打包工具另外固定在 `requirements-build.txt`。无需手动激活环境，也不要把 `.venv` 打包交付。已有旧环境时执行 `uv sync --python 3.12` 切换。

macOS 不要用 Xcode / 系统自带的 Python 3.9 和 Tk 8.5，它可能只显示空白窗口。使用 uv 管理的 Python 3.12（本机验证为 Tk 9.0）。程序会在创建窗口前拒绝 macOS 的 Tk 8.5，并输出修复命令。macOS 界面回归测试：`LEDGER_GUI_TESTS=1 uv run python -m unittest tests.test_ui -v`，会短暂打开测试窗口。

Windows 7 目标构建固定使用官方 **Python 3.8.10 32 位**，通过 uv 指定该已安装解释器，不使用 uv 自动下载的 Python 发行版。开发可使用较新 Python，但代码保持 Python 3.8 语法兼容。macOS/Linux 源码运行的数据位于 `~/.customer-ledger`，不会写入 Windows 账本路径。

## 构建 Windows EXE

### GitHub Actions 构建

将代码推送到 `master` / `main`，或在仓库的 Actions 页面手动运行 **Build Windows 7 EXE**。
流水线在 Windows 2022 上安装官方 Python 3.8.10 x86 和 uv，执行业务及真实窗口测试，使用固定版本 PyInstaller 打包。

成功后，在该次运行页面的 **Artifacts** 下载 `CustomerLedger-win7-x86`，解压取得 `CustomerLedger-win7-x86.zip` 与 `SHA256SUMS.txt`，再解压应用 ZIP，运行其中的 EXE。GitHub 构建产物保留 30 天，需登录有权限的 GitHub 账号下载。

工作流只上传程序包和校验值，不上传虚拟环境、测试账本或真实数据。Windows 7 最低目标为 SP1；如系统缺少运行库或补丁，按下方说明处理。GitHub 托管构建机为较新 Windows，构建成功不代表已经通过 Windows 7 实机验收。

### 本机 Windows 构建

在 Windows 10 或更新的构建电脑上安装 uv、官方 Python 3.8.10 32 位（包含 Tcl/Tk 和 Python Launcher），进入源码目录，双击 `build_windows.bat` 或执行：

```bat
build_windows.bat
```

没有 Python Launcher 时，传入解释器完整路径：

```bat
build_windows.bat "C:\Python38-32\python.exe"
```

脚本验证平台和 Python 版本，使用 `uv venv` 建立独立 `.build-venv`，使用 `uv pip sync` 安装锁定的构建依赖，运行核心测试和真实 Tk 界面冒烟测试，通过 PyInstaller 4.8 生成文件夹及 ZIP：

```text
dist/CustomerLedger/CustomerLedger.exe
dist/CustomerLedger-win7-x86.zip
```

首次构建需联网下载构建依赖；最终程序可完全离线使用。[uv 本身最低支持 Windows 10](https://docs.astral.sh/uv/reference/policies/platforms/)，因此构建机与目标运行机分开。PyInstaller 4.8 不正式支持 Windows 7，必须将生成的同一 x86 程序包放到 Windows 7 SP1 的 x86 和 x64 系统实测，不能用较新 Windows 上成功打包来代替 Windows 7 验收。系统若提示缺少运行库，应按 Microsoft 官方渠道安装相应 Universal CRT / Visual C++ 2015–2019 x86 运行库和系统更新，不要从非官方站点下载 DLL。

## 项目结构

- `ledger/domain.py`：金额、日期和余额规则。
- `ledger/storage.py`：数据库事务、客户与流水、备份恢复、导出、单实例锁。
- `ledger/ui.py`：Tkinter 界面。
- `main.py`：程序入口与启动处理。
- `tests/`：核心业务、持久化与文件操作测试。
- `scripts/build_windows.py`、`requirements-build.txt`：Windows 构建。
- `pyproject.toml`、`uv.lock`：uv 项目及依赖锁定。
- `scripts/package_source.py`：生成不含真实账本的源码 ZIP。
